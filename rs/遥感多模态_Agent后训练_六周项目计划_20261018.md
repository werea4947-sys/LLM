# 遥感多模态与 Agent 后训练项目计划

编制日期：2026-10-18  
项目定位：面向大模型业务算法实习的个人项目  
建议名称：面向遥感影像解译的多模态问答与工具调用后训练  
时间假设：六周，每周约 15–20 小时；若数据审核或多轮训练适配耗时较多，延长至八周。以下时间、数据规模和验收门槛均为项目建议，不是已完成结果或行业标准。

## 1. 项目目标与范围

利用已有遥感基础，完成“公开数据整理 → 专业任务构建 → 领域 SFT → 工具调用 SFT → 小规模 Agent RL → 独立评测与演示”的完整过程。

第一版使用 RGB 遥感影像，选择“目标存在判断”和“计数”两类主要任务。只有标注完整、计数口径清楚的样本才纳入精确计数；原标注是数量区间时，保留原定义，不擅自改成精确数量。若计数数据审核成本过高，先替换为场景分类。图像描述作为少量辅助任务，不作为第一阶段 RL 的主要奖励来源。

目标是证明自己能够定义问题、构建可信数据、训练模型、定位错误并完成对照实验。六周内不要求发布论文，也不预设 RL 一定有效。

第一版暂不扩展多光谱、SAR、长时序、洪涝水深预测、复杂知识库或多个工具。该项目与现有洪涝时空嵌入研究分别管理，后续再考虑连接。

## 2. 技术选型

| 组件 | 首选 | 执行说明 |
| --- | --- | --- |
| 基座模型 | Qwen/Qwen3-VL-4B-Instruct | 使用已有视觉能力，先评测再做领域适配；无需另接 CLIP |
| 备用模型 | Qwen/Qwen2.5-VL-3B-Instruct | 若首选模型与固定框架版本适配不顺，经过记录后切换 |
| 训练框架 | ms-swift | 优先在同一框架完成 SFT 与 GRPO；模型、版本、推理后端的具体组合先做小样本验证 |
| SFT 方法 | LoRA | 首轮冻结视觉编码器与连接模块，优先适配语言部分；后续是否解冻由错误分析决定 |
| 推理与采样 | Transformers 起步，随后评估 vLLM | 不在首周同时引入复杂分布式和推理服务 |
| 图像工具 | crop_image | 接受图像 ID 与像素坐标，真实执行裁剪并返回局部图 |
| 数据处理 | Python、JSONL/Parquet、Pillow；需要地理信息时使用 rasterio | 原图与训练标注分开保存，保留来源和版本 |
| 演示 | Gradio；有余力再补 FastAPI | 支持原图、问题、工具记录和结果回看 |
| 计算资源 | 已有 4 × L40 48GB | 单卡跑通后再扩展；多卡显存不会自动合并，具体批量和分辨率以实测为准 |

环境优先使用可控的 Linux GPU 环境，记录 Python、PyTorch、CUDA、Transformers、ms-swift 与推理后端版本。不要直接复用旧 TensorFlow 环境，也不要混用不同版本文档中的训练参数。

## 3. 六周计划总表

| 周次 | 核心目标 | 必做任务 | 产出 | 阶段验收 |
| --- | --- | --- | --- | --- |
| 第1周 | 确定任务与跑通基线 | 检查模型环境；审阅约100–200条公开样本；确定两类任务及答案规则；划定数据来源与评测边界；运行原模型 | 环境记录、任务说明、数据盘点、原模型预测与错误清单 | 媒体可解码、问题与图片对应；能端到端推理并保存结果；明确数据有哪些标注、缺什么 |
| 第2周 | 建立数据流水线 | 机械检查、重复与近重复检查、标注归一；按原图/区域分组；先做约300条人工审核种子，再扩展约3000–5000条训练样本 | 清洗脚本、样本规范、过滤日志、数据卡、固定划分 | 必需字段与坐标规则检查通过；测试来源隔离；审核问题已修正、隔离或明确记录 |
| 第3周 | 完成领域 SFT | 用100–300条做训练冒烟检查；检查图像加载与 loss mask；运行首轮 LoRA；分析开发集错误，最多做一次有依据的数据迭代 | SFT 配置、权重、训练日志、原模型与 SFT 对照 | 可复现训练与评测；排查格式错、图像未加载和严重退化；有结果分析，不要求必须提升 |
| 第4周 | 完成工具调用 SFT | 实现真实裁剪工具和坐标映射；先验证约50条完整交互，再按需要扩展约500–1500条审核轨迹；保留直接回答样本 | 工具执行器、交互数据、工具 SFT 模型、固定切图基线 | 验证坐标合法性、工具返回图像和上下文；无标准答案泄漏；建议合法调用率达到95%后再进入 RL |
| 第5周 | 小规模 Agent RL | 满足进入条件后实现奖励与 rollout；从约200–500个审核任务起步；限制轮次与上下文；对比 SFT 和 SFT+GRPO | RL 配置、奖励分项、轨迹、开发集分析 | 任务正确性与成本分别报告；检查奖励利用和重复调用；若进入条件未满足，则本周用于修复工具与数据 |
| 第6周 | 完成独立评测与展示 | 冻结方案后运行最终评测；整理对照、失败案例与成本；完成界面、复现文档、演示录像和项目说明 | 可运行项目、数据说明、评测表、演示、简历素材 | 他人可按说明复现关键流程；明确基座、开源数据与个人贡献；所有提升数字都有实验记录 |

六周结束的最低完成版本：领域 SFT、真实工具调用、固定流程对照、可复现评测和演示。若 RL 未完成或未有效，明确报告，不以未验证结果包装项目。

若延长至八周：第7周集中解决多轮 RL、推理采样与图像返回适配；第8周完成跨区域或跨数据来源验证。额外时间优先解决未完成验证，不增加无关模块。

## 4. 公开数据选择

| 数据 | 已核对的用途 | 本项目建议角色 | 主要风险与处理 |
| --- | --- | --- | --- |
| GeoChat / GeoChat-Instruct | 遥感领域描述、问答、分类与定位等指令任务；包含生成式指令 | 首轮 SFT 候选主数据，从符合两类主要任务的样本中取子集 | 核对原图来源、生成答案质量、坐标规则和类别映射；不用原始数据数量代替有效样本数量 |
| RSVQA | 低/高分辨率影像问答，问答信息来自 OSM | 备选主数据或额外评测候选 | 影像与 OSM 可能时空不一致；检查图像可见性和数量答案定义 |
| EarthVQA | 配准的遥感影像、地表覆盖掩膜及关系/计数等问答 | 第一周小样本审阅的另一候选；适合研究依据标注构建问题 | 类别定义、实例与连通区域计数可能不同；不能把连通区域数量直接当建筑实例数量 |

执行默认：先审阅 GeoChat 的小子集；若存在判断与计数缺乏可靠参考标注，则转向 EarthVQA/RSVQA 中可核验任务，或将计数替换为场景分类。第1周末固定一个主来源，不在首版同时混用全部数据。

EarthVQA 的参考掩膜、目标标注与标准答案用于监督或离线核验，不作为在线工具输出。新增区域或来源作为外部测试前，检查是否与训练图像及其裁剪块重合。

## 5. 数据清洗与构建流水线

原始素材入库 → 机械检查 → 来源与重复检查 → 分组划分 → 标注审核与任务构建 → 训练格式转换 → 分层抽检 → 版本发布。

| 步骤 | 操作 | 必须记录 |
| --- | --- | --- |
| 来源登记 | 记录数据集、原图 ID、来源链接、使用条件及可用元数据 | source_id、license、original_image_id、版本 |
| 机械检查 | 解码图片；检查空字段、角色、尺寸和坐标；处理编码问题 | 检查结果及失败原因 |
| 重复检查 | 文件哈希识别完全重复；感知哈希/特征检索辅助找近重复，人工确认 | 重复组与保留理由 |
| 划分 | 保留官方划分；新增样本按原图、区域或采集来源分组；检查跨集合重复 | split、group_id、随机种子及划分规则 |
| 语义审核 | 检查问题可回答性、答案依据、计数定义和类别一致性 | reviewer、review_status、error_type |
| 任务构建 | 从可靠标注生成问题；允许改写，但不能引入没有证据的属性或因果解释 | task_type、label_source、生成模板 |
| 工具轨迹构建 | 执行真实裁剪；保存动作、观察与最终回答；混入直接回答和失败恢复轨迹 | 工具版本、参数、返回图与最终状态 |
| 发布 | 导出固定版本的训练/开发/测试数据、数据卡及统计 | 样本数、原图数、任务比例、过滤原因与版本 |

说明：

- 同一原图的所有问题、裁剪和改写保持在同一划分中。
- 问题相同但图像不同，不自动认定重复。
- 原始答案没有物体实例计数依据时，不自行补造“精确数量真值”。
- 模糊或信息不足可以构成“无法判断”任务，但需审核原因；原数据没有该标注时不得擅自替换标准答案。
- 图像缺少可靠地理信息时，不构建真实经纬度、面积、距离和朝向问答。
- 对模型生成答案按来源和任务类型分层审核；生成模型的自评分不等于正确率。
- 开发集可用于错误分析；不根据最终测试题反复补造训练样本。

建议字段：sample_id、source_id、original_image_id、group_id、image_path、question、answer、task_type、reference_annotation、label_source、review_status、split、version。工具数据另存实际 messages/动作与观察记录。

## 6. SFT 与 Agent 训练设计

### 6.1 领域 SFT

输入：RGB 遥感影像与问题。  
输出：规范化答案，必要时附简短依据。  
初始策略：LoRA 适配语言部分，冻结视觉编码器与连接模块。

训练前人工检查一小批实际送入模型的图像、文本、token 和 loss mask，确认答案未被截断、媒体确实被加载。先跑小样本，再做完整首轮。若后续调整视觉模块，单独记录训练参数量和成本。

### 6.2 工具调用 SFT

唯一工具：

```text
crop_image(image_id, x1, y1, x2, y2)
```

第一版统一使用原图像素坐标。程序验证 0 ≤ x1 < x2 ≤ width、0 ≤ y1 < y2 ≤ height，执行裁剪并返回局部图像及坐标元数据。规范工具异常的返回方式。工具不得返回参考标签、目标框或标准答案。

轨迹示例（仅说明流程，不是已获得的训练样本）：

用户提问 → 模型请求查看局部 → 程序实际裁剪 → 返回局部图 → 模型回答或继续查看。

先允许直接回答与最多两次裁剪，作为可调整的初始约束。查看局部不能增加原图没有的细节；看不清应允许无法可靠判断。初始视觉输入的信息预算与高分辨率、固定切图基线都要记录。

### 6.3 Agent RL

进入条件：

1. 完整 rollout 已跑通，图像工具返回能够被模型正确读取。
2. 工具调用 SFT 基本稳定，合法调用率建议达到95%；此门槛只是项目自定。
3. 问答有可靠可核验目标，开发集中确实存在需要决策的困难样本。
4. 基础任务未完全饱和；如果同组生成结果奖励总相同，先检查任务难度、采样和奖励定义。
5. 已建立固定切图和工具 SFT 对照。

奖励起点：答案正确性奖励 − 工具调用成本 − 无效调用惩罚。不要预设权重；先测每一项分布，再确定权重。规则格式只作为辅助，不让格式收益盖过答错惩罚。不以“必须调用工具”作为成功标准，不单独以 CLIP 相似度奖励事实正确性。

先冻结视觉编码器与连接模块，在语言部分 LoRA 上尝试小规模 GRPO。采样组大小、最大输出长度、最大图像数和训练/采样资源分配均经冒烟测试后确定。

## 7. 评测矩阵

| 方法 | 目的 |
| --- | --- |
| 原始 Qwen-VL，直接回答 | 明确基座已有能力 |
| 领域 SFT，直接回答 | 判断领域数据适配作用 |
| 固定切图 + 同一问答模型 | 检查简单流程是否足够 |
| 工具调用 SFT | 判断交互轨迹训练作用 |
| 工具调用 SFT + GRPO | 判断 RL 在正确率、调用次数或成本上的额外作用 |
| 不输入图像，仅输入问题 | 检查语言先验和标签分布偏差 |

按存在判断和计数分别报告准确率；计数为精确数字时可补充 MAE，数量区间则按数据集定义评测。定位任务只有在后续加入且有可靠标注时才报告 IoU 等指标。

共同记录：总样本数与独立原图数、任务成功率、合法/无效调用率、平均调用次数、推理耗时、峰值显存。明确是否包含工具耗时和图像预处理。预算匹配时比较不同方法，避免把更多像素或更多调用带来的收益全部归因于 RL。

小规模评测建议覆盖约200–500条审核问答，并报告来源和原图数；不将此数量视为统计充分的保证。同图多题存在相关性，可按原图分组分析不确定性。公开基准可能已被基座见过，不能由基准得分直接推断新区域泛化能力。

若清洗带来改善，补充“等量随机数据 vs 等量质量筛选数据”的对照，以帮助区分数量与质量效应。有时间时对关键训练比较运行多个随机种子。

## 8. 资源与范围控制

| 阶段 | 初始资源策略 | 扩展条件 |
| --- | --- | --- |
| 数据处理 | CPU 做解码、校验、索引；需要时批量提取特征 | 先确认 I/O 是否为瓶颈 |
| 原模型与 SFT 冒烟 | 单张 L40，控制分辨率与序列长度 | 实测前不承诺最大 batch |
| SFT 正式实验 | 单卡或多卡 DDP/分片，按实测选择 | 记录有效 batch、累计步数和训练 token/图像预算 |
| RL | 先小任务量与短 rollout，再评估训练/采样分配 | 确认硬件互联、CPU内存及框架版本；不预先固定“几卡训练几卡采样” |
| 模型对比 | 首先只做一个4B级模型 | 数据与工具流程稳定后再增加第二模型 |

不用提前租卡。当前已有资源足以开展规划中的小规模验证，但完整多轮 RL 的可行配置仍取决于实际图像长度、采样数量、版本及资源可用时长。
